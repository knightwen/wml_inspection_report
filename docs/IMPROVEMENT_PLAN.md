# 检查报告工作台改进计划

- 评估日期：2026-10-11
- 状态：待实施
- 范围：当前开发分支；按阶段完成并验证后，再确认发布新版本。

## 当前评估

核心流程已适合日常试用：报告信息、人员库、常用措辞库、照片编辑、检查项保存与排序、Word 导出和报告预览已形成完整流程。下一阶段优先提高稳定性、数据恢复能力和便携使用体验。

当前验证结果：14 项应用测试通过；内置模板和 4 份测试报告均无 Open XML 格式错误。此前已验证照片编辑、拖动排序和预览的浏览器操作，但尚未建立自动化浏览器回归测试，也尚未重新验证包含最新功能的便携 EXE。

下列问题与改进均为计划，不代表已经修复或完成。

## 第一阶段：发布前稳定性

### 1. 修复手动姓名的人员信息残留

- [ ] 从人员库切换到手动姓名时，明确清除或重新确认原人员的资质、职位和人员引用。
- [ ] 保持既有报告中的人员信息快照，不因编辑人员库而自动改变。
- [ ] 增加“选人员 → 改为手动姓名 → 保存 → 导出”的回归验证。

验收：新填写的姓名不会错误继承上一人的资质和职位；报告界面与 Word 内容一致。

### 2. 加强保存中关闭页面与多页面冲突的保护

- [ ] 记录待提交、排队中和提交中的保存状态，完善关闭或刷新页面时的提示。
- [ ] 保存成功提示应准确对应当前编辑内容，避免仍有排队修改时显示全部已保存。
- [ ] 多页面发生版本冲突时，提供保留当前修改的副本或导出入口，再加载服务器版本。
- [ ] 验证连续快速编辑、保存失败、关闭页面和多页面编辑场景。

验收：用户能明确判断修改是否已保存；冲突处理不要求先丢弃当前修改。

### 3. 改进报告预览任务

- [ ] 预览使用固定草稿快照；Word 转换和逐页渲染期间不长期占用保存锁。
- [ ] 展示生成、转换和渲染状态，提供失败后重试的明确入口。
- [ ] 检测 Microsoft Word 转换能力，未安装或不可用时说明限制，保持 DOCX 生成功能可用。
- [ ] 确保转换失败或超时后释放所创建的文档和进程资源，不影响用户已有的 Word 文档。
- [ ] 保持“下载此份 Word”与当前预览使用同一份报告快照。

验收：预览期间仍能正常保存；成功、失败、超时和无 Word 环境均有清晰结果。

### 4. 验证最新 Windows 便携包

- [ ] 重新构建包含照片编辑、排序动画、Word 修复和预览功能的本地 EXE / ZIP。
- [ ] 扩展便携 EXE 验证，覆盖新照片编辑操作和预览依赖的打包完整性。
- [ ] 验证中文及空格路径、无 Python 环境、数据目录不可写和重复启动。
- [ ] 分别验证有 Microsoft Word 和无 Microsoft Word 的电脑；后者应仍能编辑草稿和生成 DOCX。
- [ ] 增加关键浏览器回归场景：人员选择、文字库连续选择、照片编辑、排序、保存和预览。
- [ ] 同步 README、便携包使用说明及版本信息，准确说明预览所需条件。

验收：下载并解压完整 ZIP 后可正常启动和完成核心流程；当前测试通过后再征求发布确认。

## 第二阶段：日常使用与数据管理

### 5. 历史恢复与完整备份

- [ ] 在目前仅保留上一份草稿的基础上，增加按时间或关键操作保留的历史版本。
- [ ] 提供可查看并恢复历史版本的界面，恢复前保留当前版本。
- [ ] 保留单份草稿备份，并增加完整工作台备份，包含草稿、照片、人员库和自定义文字库。
- [ ] 完善导入校验、失败回滚及跨电脑恢复验证。
- [ ] 隔离损坏的单份草稿，避免一份文件损坏阻止整个草稿列表打开。

验收：误改或误删后有明确恢复路径；迁移到另一台电脑可恢复所选择范围的数据和标准库。

### 6. 分开评级与补充说明

- [ ] 将基本等级与补充说明分别保存，保留手动填写能力。
- [ ] 兼容现有草稿，迁移时不丢失原始文字；无法确定等级时保留自定义值。
- [ ] Word 的等级着色、后续筛选和统计使用基本等级，说明作为附加内容显示。

验收：例如 High 加补充说明仍保留 High 的标准颜色，同时完整导出补充说明。

### 7. 草稿管理与缓存清理

- [ ] 增加草稿搜索、复制和归档，方便报告数量增加后的查找与复用。
- [ ] 为预览产生的 DOCX、PDF 和页图制定缓存保留策略。
- [ ] 缓存清理与用户主动保存的报告、原始照片分开处理，保持当前打开的预览可用。
- [ ] 显示数据位置和存储占用，提供清晰的备份与整理入口。

验收：报告列表易于查找；预览缓存有边界，清理不会破坏草稿、原图或用户保留的报告。

### 8. 启动与重新打开工作台

- [ ] 双击程序可重新打开正在运行实例的正确页面。
- [ ] 服务已退出、访问凭证过期或页面连接失败时，提供容易理解的操作提示。
- [ ] 为开发预览提供固定启动入口，减少手动输入命令和复制网址。
- [ ] 保留本地访问保护，避免用户需要自行管理访问凭证。

验收：正常使用不需要手动找端口、凭证或直接打开 index.html；重启后能继续使用原草稿。

## 第三阶段：报告与照片功能完善

### 9. 在应用中完成整份报告

- [ ] 根据实际报告流程，支持填写 Introduction、修复方案、Conclusion 和费用估算。
- [ ] 空白与已有内容的显示、保存、预览和 Word 导出保持一致。
- [ ] 完善目录更新、长文字、多照片和分页验证。

验收：如选择在应用中填写这些章节，可完成对应报告内容，无需再到 Word 中逐项补录。

### 10. 照片恢复与可编辑标注

- [ ] 优先提供恢复原图功能，明确当前照片与保留原始文件的关系。
- [ ] 后续考虑保存裁剪和标注操作，使重新打开后可移动、修改或删除既有标注。
- [ ] 将编辑信息纳入备份和恢复，确保 Word 仍使用确认后的最终图像。

验收：原图可恢复；若实现可编辑标注，重新打开、跨电脑恢复和导出后的结果保持一致。

## 推进顺序与发布约束

1. 先完成第一阶段的四项发布前工作。
2. 再完成历史恢复、完整备份及日常管理。
3. 根据实际使用反馈推进完整报告内容和照片标注能力。
4. 各项完成后记录验证结果，再勾选任务。
5. 开发分支提交和推送不等于版本发布。未经确认，不创建发布标签或发布新版本。
