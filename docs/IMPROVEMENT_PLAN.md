# 检查报告工作台改进计划

- 评估日期：2026-10-11
- 状态：第一阶段已实施并通过本地验证；独立电脑复核待发布前完成
- 范围：当前开发分支；按阶段完成并验证后，再确认发布新版本。

## 当前评估

核心流程已适合日常试用：报告信息、人员库、常用措辞库、照片编辑、检查项保存与排序、Word 导出和报告预览已形成完整流程。下一阶段优先提高稳定性、数据恢复能力和便携使用体验。

当前验证结果：20 项应用测试、保存队列测试和自动化浏览器回归通过；内置模板及 6 份测试报告均无 Open XML 格式错误。最新便携 EXE / ZIP 已通过解压运行验证，并完成真实 Word 转换与 PDFium 逐页渲染验证。

第一阶段勾选项已实施并验证；第二、三阶段仍为计划。本次版本号保持 0.1.3，仅更新本地预览和本地构建，没有推送、创建标签或发布新版本。

## 第一阶段：发布前稳定性

### 1. 修复手动姓名的人员信息残留

- [x] 从人员库切换到手动姓名时，明确清除或重新确认原人员的资质、职位和人员引用。
- [x] 保持既有报告中的人员信息快照，不因编辑人员库而自动改变。
- [x] 增加“选人员 → 改为手动姓名 → 保存 → 导出”的回归验证。

验收：新填写的姓名不会错误继承上一人的资质和职位；报告界面与 Word 内容一致。

### 2. 加强保存中关闭页面与多页面冲突的保护

- [x] 记录待提交、排队中和提交中的保存状态，完善关闭或刷新页面时的提示。

- [x] 多页面发生版本冲突时，提供保留当前修改的副本或导出入口，再加载服务器版本。
- [x] 验证连续快速编辑、保存失败、关闭页面和多页面编辑场景。

验收：用户能明确判断修改是否已保存；冲突处理不要求先丢弃当前修改。

### 3. 改进报告预览任务

## 第二阶段：日常使用与数据管理

- [ ] 在目前仅保留上一份草稿的基础上，增加按时间或关键操作保留的历史版本。
- [ ] 提供可查看并恢复历史版本的界面，恢复前保留当前版本。

验收：报告列表易于查找；预览缓存有边界，清理不会破坏草稿、原图或用户保留的报告。

- [ ] 双击程序可重新打开正在运行实例的正确页面。

### 10. 照片恢复与可编辑标注

- [ ] 将编辑信息纳入备份和恢复，确保 Word 仍使用确认后的最终图像。

验收：原图可恢复；若实现可编辑标注，重新打开、跨电脑恢复和导出后的结果保持一致。

## 推进顺序与发布约束

1. 先完成第一阶段的四项发布前工作。
2. 再完成历史恢复、完整备份及日常管理。

4. 各项完成后记录验证结果，再勾选任务。
5. 开发分支提交和推送不等于版本发布。未经确认，不创建发布标签或发布新版本。
